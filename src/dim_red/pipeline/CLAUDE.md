# CLAUDE.md

Guidance for `src/dim_red/pipeline/`.

`RunConfig` (YAML) drives everything. `model_kind` ∈ `supcon` (default), `supcon_mace`, `cgcnn`; `data_source` ∈ `mp` (`fetch:` block) / `pyxtal` (`pyxtal:` block). The encoder architecture lives in the `encoder:` block (`EncoderConfig`; the legacy `vae:` block name is still read and merged). Removed/deprecated keys (`normalize_distances`, `jitter_std_relative`, `optimizer`, `beta`, `decoder_hidden_dim`, `mirror`) are ignored quietly when loading saved `config.yaml`s; other unknown keys warn; `vae`/`autoencoder`/`mace` as `model:` and `classification.mode: family_and_spacegroup`/`tails.hierarchical` raise explicit errors. The optimizer is always Adam. Dataset cache keys deliberately pin the removed fields to their old defaults (`normalize_distances=False`, `jitter_std_relative=False`) so existing caches stay valid. Shared small helpers of `single_run`/`tail_training` live in `_common.py`.

Entry points (`pyproject` console scripts): `dimred-run`, `dimred-sweep`, `dimred-rerun`, `dimred-compare`, `dimred-apply`, `dimred-train-tail`, `dimred-benchmark` (`cli.py`, no flag-style interface).

**`pipeline.tail_training`** is phase 2 of the body/tail workflow (see `src/dim_red/supcon/CLAUDE.md`). `_TAIL_MODEL_KINDS = {"classification": (supcon, cgcnn, supcon_mace), "visualization": (supcon, cgcnn, supcon_mace), "hierarchical_supcon": (supcon, supcon_mace)}`. `hierarchical_supcon` = stage 1 family classifier + one per-family SupCon "SG" expert (encoder + projection trained on that family's native features, then classifier + visualizer), writing to `tails/<output_subdir>/`. `_compute_native_soap_features`/`_compute_native_mace_features` recompute the per-family inputs.

**`SupConConfig`/`HierarchicalSupconTailConfig` defaults are the `best_combo` (round 15) + round 16 per-family visualization tuning** (`mode: family_only`, `tau: 0.05`, `distance: cosine`; experts `sg_encoder_hidden_dim: [256, 128]`, `sg_latent_dim: 32`, `sg_visualization_hidden_dim: [64, 32]` with `sg_visualization_hidden_dim_by_family` overriding it per family; pass `{}` to disable the per-family override). See `configs/single_run_supcon_best_combo.example.yaml`, `configs/tail_train_hierarchical_supcon_best_combo.example.yaml`, `experiments/round15_dims_notes.md`.

`RunConfig.tails` (`AutoTailsConfig`, YAML `tails:` with `classification`/`visualization`/`train` sub-blocks) makes `run_single` call `train_tail` right after phase 1, so one `dimred-run`/`dimred-sweep` trains several tails; a failure aborts the run. `classification` is ignored for model kinds it doesn't support; swept `tails.*` paths work like any other field. Inference with `hierarchical_supcon` experts is not yet provided by the library (see `REFACTOR_TODO.md`).

**Train/val split is grouped by `material_id`, not by row** (`pipeline.single_run.run_single`'s `_split_indices_grouped`, used for every `model_kind` instead of the old plain per-row `_split_indices`): `dim_red.augmentation.augment_structures` keeps `material_id` identical across an original structure and every one of its augmented (jittered/vacancy) copies, so a plain per-row shuffle routinely put a jittered/vacancy twin of a training structure into validation — val accuracy under that scheme was inflated by near-duplicate leakage between train and val, not genuine generalization to unseen structures (a held-out pyxtal test set with a fresh seed, see `examples/evaluate_holdout_pyxtal.py`, showed the gap directly: family accuracy dropping from ~0.95 val to ~0.5 on structures sharing no augmentation lineage with training). `_split_indices_grouped` fixes this by shuffling at the *group* level instead (unique `material_id`s, with `val_ratio` applied to the group count, not the row count) so every copy of a given structure lands on the same side of the split. When `material_id` is already unique per row (no augmentation configured, or augmentation that never actually duplicates a `material_id`), grouping degenerates to exactly one group per row and falls back to the old `_split_indices` call, reproducing its split byte-for-byte — **every pre-existing, non-augmented config's split is completely unchanged by this fix**; only augmented datasets, which never had a same-side guarantee before, get a different (and now trustworthy) split. `pipeline.tail_training` reads this same split back out of `embeddings.npz["split"]` unmodified (see below), so the fix reaches every tail trained on top of a body too, with no changes needed there.

`pipeline.compare.classification_accuracies_from_npz`/`hierarchical_accuracies_from_npz` (and therefore `pipeline.benchmark.run_classification_accuracies`/`benchmark_row`) now report **val-only** accuracy under the bare `family`/`spacegroup`(/`spacegroup_oracle`) keys instead of train+val pooled, whenever the source npz carries a `split` array (every real run's `embeddings.npz`/`tail_predictions.npz` does) — `family_all`/`family_train`/`family_val` (and the `spacegroup`/`spacegroup_oracle` equivalents) are all reported alongside for reference. **Deliberate default-behavior change**: a pre-existing benchmark CSV's `family`/`spacegroup` columns meant the pooled number, which is always ≥ the val-only one, so don't compare old and new benchmark rows on those bare columns without normalizing to `_all` first. An npz with no `split` array at all (hand-built test fixtures, or an artifact predating `split`) keeps the original pooled-only behavior, no `_all`/`_train`/`_val` keys added.

**`pipeline.inference`** (`load_trained_run`, `encode_structures`, `plot_applied_in_latent_space`, `apply_model_to_structures`; `dimred-apply <structures.extxyz> <run_dir>`) applies a completed run to new structures. `load_trained_run` needs `config.yaml`, `dataset.extxyz`, `model_params.msgpack`, `embeddings.npz`; standardization stats come from `embeddings.npz` (`feature_mean`/`feature_std`, with a SOAP-recompute fallback for old runs). New structures go through the same recovered pipeline; species must be among the run's. 2D plots fit one shared UMAP on the original embeddings and `transform` the new points. cgcnn has its own SOAP-free branches (`src/dim_red/cgcnn/CLAUDE.md`).

**`pipeline.benchmark`** (`dimred-benchmark <runs-or-sweeps>... --output <csv> [--plot]`) writes one wide CSV *quantifying* run quality across `model_kind`s — it never ranks or picks a "best" run. Per row: accuracies from `classification_accuracies_from_npz` (the run's own npz, else `tails/classification/tail_predictions.npz`, else a `tails/hierarchical_supcon*` one), 2D-view quality (`family_2d`/`spacegroup_2d` from `analysis.metrics.embedding_quality_metrics` on a viz-tail embedding, native 2D or PCA), `wall_clock_seconds`, key hyperparameters, `final_*` losses (not comparable across kinds), and native-dimension embedding quality. `--plot` adds box-plot PNGs per `model_kind`. See `configs/benchmark_pyxtal_base.example.yaml`, `configs/tuning_sweep_{supcon,cgcnn}.example.yaml`.

See the repo-root `CLAUDE.md` for the early-stopping convention, `src/dim_red/supcon/CLAUDE.md` for phase 1/2, `src/dim_red/cgcnn/CLAUDE.md` and `src/dim_red/mace/CLAUDE.md` for the other bodies.
