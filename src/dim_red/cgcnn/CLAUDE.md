# CLAUDE.md

Guidance for `src/dim_red/cgcnn/` (moved out of the repo-root `CLAUDE.md` since it's specific to this directory).

`cgcnn/` is a hand-written JAX/Flax reimplementation of Crystal Graph Convolutional Neural Networks (Xie & Grossman 2018, https://github.com/txie-93/cgcnn) — unlike `vae`/`autoencoder`/`supcon`, it never touches SOAP at all: it builds its own graph representation directly from a crystal's atoms and bonds. Organizationally it mirrors `supcon/`'s file layout (own `model.py`/`training.py`/`__init__.py` with the same PEP 562 lazy-import pattern, `ClassifierHead`/`apply_family_mask` duplicated rather than imported from `vae`/`autoencoder`, so this package stays independent), but its training semantics mirror `autoencoder`'s single-phase `aux_heads` pattern instead of `supcon`'s two-phase contrastive-pretrain-then-freeze-and-train-a-tail design: the body and classifier head(s) are trained *jointly* via cross-entropy on family (+ optional spacegroup) labels, with no reconstruction/KL/contrastive loss anywhere.

Two deliberate deviations from the original paper, both because this codebase's environment has no `torch`/`torch_geometric`/`dgl`/`jraph` (verified absent; the rest of the codebase is uniformly JAX/Flax/Optax):

- **Atom features are keyed by a per-structure LOCAL species slot, not a real atomic number or the original's fixed 92-dim `atom_init.json` table.** Per explicit design requirement: this model must distinguish species A from species B within a structure but must never care which real chemical element either one is. `graph.py`'s `_local_species_indices` sorts each structure's distinct atomic numbers ascending and remaps them to slots `1..k` (`0` reserved for padding) — a binary Fe/O structure and a binary Na/Cl structure with the same geometry produce identical output. This fits `dim_red.generate`'s pyxtal path perfectly, whose species are already sampled from an arbitrary placeholder pool with no chemical meaning. A consequence: since the mapping is a deterministic per-structure rule (not a learned/memorized global table), there is **no species vocabulary anywhere** — `encode_structures` on brand-new structures generalizes automatically to any element combination, seen or unseen during training, as long as the structure has at most `GraphConfig.max_species` distinct species.
- **`nn.LayerNorm` instead of the original's two `BatchNorm1d`s.** Real batch-statistics BatchNorm needs mutable `batch_stats`, a `train`/`eval` flag threaded through every call, and `nn.vmap` with an `axis_name` for correct cross-sample statistics — machinery no other model wrapper in this codebase has (`VAE`/`Autoencoder`/`SupConEncoder` all expose a single pure `params` pytree). `LayerNorm` (per-sample, no mutable state) preserves the gating/residual formula while keeping `CGCNNEncoder` exactly as simple as its siblings. A true-BatchNorm variant is a documented, deliberately-deferred follow-up, not implemented here.

- `graph.py` (pure NumPy + ASE, **no jax dependency at all**): `_neighbors_for_structure` uses `ase.neighborlist.neighbor_list('ijd', atoms, radius)` rather than pymatgen's `Structure.get_all_neighbors` or a naive minimum-image-convention distance matrix — the latter (e.g. `dim_red.soap`'s `atoms.get_all_distances(mic=True)`) is only valid for cutoffs below half the cell's shortest perpendicular width, routinely violated by CGCNN's own default `radius=8.0` against small pyxtal-generated cells; `ase.neighborlist` handles periodic images correctly via cell-shift search regardless. Each atom keeps its `max_num_nbr` closest neighbors, zero-padded/masked when fewer exist (pad index → atom 0, pad distance → `radius`, mask → `0.0` — mirrors the original's own padding scheme; downstream must always multiply by `nbr_mask`). `_gaussian_expand` expands distances into a Gaussian radial basis (`exp(-((d-filter_k)^2)/step^2)`, `n_gaussian = round((dmax-dmin)/step) + 1`) — bond features are real geometric distances, unaffected by the species-agnostic design. `atoms_to_graph`/`atoms_list_to_graph_arrays` build one structure's / a whole dataset's graph, the latter padding every structure to a common `max_atoms` (`None` → the largest structure's own atom count, resolved fresh per call). **`max_atoms` is a per-call array-shape convenience, not a baked-in architecture constant** — no param in the model depends on it (`Dense`/`Embed` only ever see the trailing feature axis), so training-time and inference-time `max_atoms` can differ freely; a brand-new structure with *more* atoms than any training structure works with zero compatibility issue. Raises if an explicit `max_atoms` is smaller than some structure's real atom count, or if any structure has more than `max_species` distinct species.
- `database.py`: `GraphDatabase`, mirroring `vae.database.VAEDatabase`'s API (`train_val_split(val_ratio, seed)`) generalized to 5 parallel arrays (`local_species_idx`/`nbr_idx`/`nbr_fea`/`nbr_mask`/`atom_mask`) instead of one flat matrix — a crystal graph can't be one row of a fixed-width matrix the way a SOAP descriptor can. `as_tuple()` feeds directly into `training.py`'s batch-iteration helpers (duplicated from `dim_red.autoencoder.training`, already rank-agnostic there, so they work unchanged on these 2D/3D/4D arrays with zero modification). `__getitem__` row-indexes all five arrays at once.
- `model.py`: `ConvLayer` (the gated graph-convolution layer) does a **batched gather with no internal `jax.vmap`** — every graph array carries a leading batch dim, and `atom_fea[batch_idx, nbr_idx]` (batched advanced indexing) gathers each atom's neighbors' features directly. Forward pass: concat `[self, neighbor, bond]` features → `Dense(2*atom_fea_len)` → `LayerNorm` → split into `(filter, core)` → `sigmoid(filter) * softplus(core)` → mask by `nbr_mask` → sum over the neighbor axis → `LayerNorm` → residual add with the layer's own input → `softplus` → mask by `atom_mask`. `CGCNNBodyModule`: `nn.Embed(num_embeddings=max_species + 1, features=atom_fea_len)` keyed by `local_species_idx` → `n_conv` stacked `ConvLayer`s → masked mean pooling over atoms → `n_h` `Dense`+`softplus` blocks → final `Dense(latent_dim)`. `CGCNNEncoderModule` composes the body with optional `family_head`/`spacegroup_head` (mirrors `AutoencoderModule`'s `setup()`/`classify_family`/`classify_spacegroup`/`init_all` shape, minus `decode` — no decoder at all, like `SupConEncoder`). `CGCNNEncoder` (the high-level wrapper) mirrors `Autoencoder`'s shape exactly (mutable `params`, `encode`/`classify_family`/`classify_spacegroup`, `*_with_params` variants) except `encode`/`encode_with_params` take a graph batch (the 5-array tuple) instead of a flat `(batch, features)` array; `max_species` is exposed as a named constructor arg (not a raw `num_embeddings`), with the `+1`-for-padding handled internally.
- `training.py`: near-verbatim specialization of `dim_red.autoencoder.training`, minus the reconstruction term. `train_family_ids`/`val_family_ids` are **required** (not `Optional`, unlike `train_vae`/`train_autoencoder`) — CGCNN has no other training objective at all, so a family-less call would be a pure no-op that silently trains nothing; `train_cgcnn` raises immediately if either is `None`. `_iter_batches`/`_make_optimizer`/`_prepare_padded_batches`/`_make_eval_epoch` are verbatim duplicates of `autoencoder.training`'s (confirmed rank-agnostic by reading the source, so no modification needed for the graph arrays' higher rank). Loss = `optax.softmax_cross_entropy_with_integer_labels` on family (+ optional family-masked spacegroup via `apply_family_mask`, same mechanism as `vae`/`autoencoder`). Same early-stopping mechanism (duplicated code, same field names) as every other training loop in this codebase.

`pipeline` integration (see `src/dim_red/pipeline/CLAUDE.md` for the general `RunConfig`/`model_kind` dispatch pattern this follows):

- `pipeline.config.GraphConfig` (YAML: top-level `graph:` block) holds CGCNN's graph-construction + architecture hyperparameters (`radius`/`max_num_nbr`/`dmin`/`dmax`/`step`/`max_species`/`atom_fea_len`/`n_conv`/`h_fea_len`/`n_h`), used *instead of* `soap:` for `model_kind: cgcnn`. `latent_dim` is deliberately **not** a `GraphConfig` field — it's read from the shared `vae:` block (`vae.latent_dim`) instead, the same "shared field, model-kind-specific subset" precedent `supcon` already sets; every other `vae:` field is ignored for `cgcnn`. `graph_kwargs()` returns only the graph-construction subset (not the architecture-only fields), used both for `atoms_list_to_graph_arrays` and as the dataset-cache key's hashed payload. `RunConfig.__post_init__` requires `aux_heads.mode != "none"` whenever `model_kind == "cgcnn"` (no reconstruction/contrastive fallback objective exists to fall back to). `aux_heads:` itself (mode/lambda weights/head width) is reused unmodified from `vae`/`autoencoder` — CGCNN's classification design is structurally identical.
- `pipeline.dataset_cache.build_graph_dataset_for_run` (+ `get_or_build_cgcnn_dataset`/`get_or_build_pyxtal_cgcnn_dataset`) is the graph-based counterpart to `build_dataset_for_run`, used only when `model_kind == "cgcnn"`. The fetch/generate/augment/cache-raw-structures-to-`<hash>.extxyz` plumbing is reused **unchanged** (all of it operates on plain `ase.Atoms`, agnostic to downstream featurization) — only feature computation (`_compute_graphs`, no standardization step needed since Gaussian-expanded distances are already bounded to `[0, 1]`) and the cache array schema (`_GRAPH_CACHE_ARRAY_KEYS`, hash prefixed `"cgcnn-"`/`"cgcnn-pyxtal-"` so it can never collide with a SOAP cache hash) differ. Returns a 5-element tuple (no `feature_mean`/`feature_std`, unlike the 7-element SOAP return shape).
- `pipeline.single_run.run_single`: an `is_cgcnn` branch parallel to `is_supcon`/`is_vae` at every stage (dataset build, train/val split via `GraphDatabase`, model construction, `TrainConfig`, the training call, full-dataset encode, `embeddings_payload`). `embeddings.npz` **omits `features`/`feature_mean`/`feature_std`** entirely for cgcnn runs (no natural flat feature vector or standardization step exists for graph features) — a documented consequence is `pipeline.compare`'s classical-baseline (PCA/UMAP-on-`features`) comparisons have nothing to fit against for cgcnn runs. Unlike `supcon` (which has no classifier heads and skips the post-hoc family/spacegroup-probability inference block entirely), cgcnn **does** have heads (its only training objective), so that block runs for it exactly like `vae`/`autoencoder` — `family_probs`/`spacegroup_probs` are saved. Both classification and visualization auto-tails (`RunConfig.tails`) are allowed for `model_kind == "cgcnn"`, not just `"supcon"`.
- `pipeline.inference.load_trained_run`: an early `model_kind == "cgcnn"` branch sets `species=[]`/`feature_mean=zeros(0)`/`feature_std=ones(0)`/`input_dim=0` (inert placeholders, kept only so `LoadedRun`'s shape stays uniform across every model kind) **before** the `"feature_mean" in embeddings` check, so the SOAP-recompute fallback (for pre-existing runs missing those fields) never fires for a cgcnn run — `dataset.extxyz` isn't even read in this branch. `encode_structures`' cgcnn branch calls `atoms_list_to_graph_arrays` fresh on the new structures (own `max_atoms`, independent of training's) instead of `_raw_soap_matrix`/`apply_standardization`.
- `pipeline.tail_training.train_tail`'s guard is `model_kind not in ("supcon", "cgcnn")` (not just `!= "supcon"`) — everything downstream of that guard already operates purely on `embeddings.npz` arrays, architecture-agnostic, so `dim_red.supcon.tail_training`'s phase-2 training loops are reused as-is regardless of which body produced the representations. A classification tail is redundant with CGCNN's own built-in heads but harmless, useful for ablation/comparison; a visualization tail is genuinely useful since `vae.latent_dim` need not be 2.

See `configs/single_run_cgcnn.example.yaml`/`configs/sweep_cgcnn.example.yaml`.
