## Environment

This project must be run inside the conda environment `dmred` (located at `/home/seraftu/miniconda3/envs/dmred`). In a persistent terminal session, run `conda activate dmred` once, verify it's active (`$CONDA_DEFAULT_ENV` should equal `dmred`), then run Python/pip/pytest commands directly without prefixing them with `conda run -n dmred`.

Dependencies are declared in `pyproject.toml` (core + extras); assume everything needed (numpy, scikit-learn, umap-learn, dscribe, ase, pymatgen, mp-api, jax, flax, optax, matplotlib, pyxtal, jupyter/nbformat/nbconvert/ipykernel) is already installed in the `dmred` environment and don't `pip install` anything. `mace_jax` is optional and only needed for `model_kind: supcon_mace`.

## Architecture

`src/dim_red/` is a materials-science dimensionality-reduction toolkit with several model kinds sharing one pipeline:

- **Data ingestion** (`fetch.py`): pulls crystal structures from the Materials Project API (`mp_api`) filtered by crystal system, converts pymatgen `Structure` objects to ASE `Atoms` via `AseAtomsAdaptor`, and stashes the `material_id` on `atoms.info`.
- **`augmentation.py`**: diversifies a fetched (or generated) structure database via data augmentation — `augment_structures`/`AugmentationConfig` apply configurable-probability positional jitter (simulated thermal noise: small Gaussian displacements of every atom) and/or vacancy (random atom removal) to each structure, producing `n_augmented` tagged copies per input . `_augment_once` guarantees every augmented copy has at least one of jitter/vacancy actually applied to it (independent probability rolls for each; if *neither* succeeds, one is forced on rather than the copy coming out identical to the original) — the corollary being that if only one mechanism is configured at all (`jitter_std > 0` xor `vacancy_atom_probability > 0`), that one applies to every augmented copy regardless of its own probability, since it's the only thing that can be forced. Vacancy removal is capped by `max_vacancies` (`None` default = uncapped) rather than a minimum-atoms floor — it always keeps at least 1 atom regardless of that cap, but doesn't otherwise guarantee a minimum count. If `AugmentationConfig.supercell_radius` is set, `augment_structures` first runs every input structure through `make_supercell_for_radius` (once per structure, before building the kept-original copy and any augmented ones) -- repeats the cell an integer number of times along each periodic lattice vector so a sphere of that radius (Angstroms) fits inside without touching its own periodic image (the standard "perpendicular cell width >= 2 * radius" sizing rule, computed independently per axis off the *original* unrepeated cell since repeating other axes doesn't change a given axis's perpendicular width). Meant for unit cells too small to meaningfully augment -- pyxtal can generate cells holding as few as 1-2 atoms -- `None` (default) skips this step, current behavior unchanged. Wired in through the pipeline's own mirror dataclass `pipeline.config.AugmentationConfig` (kept separate so parsing a config doesn't import `dim_red.fetch` -> `mp_api`/`pymatgen`): `RunConfig.augmentation` for cgcnn, `data.augmentation` of each FullStack stack; `pipeline.dataset_cache.resolve_augmentation` converts it (seed falls back to the stack/run seed) and the builders run `augment_structures` right before featurization. The settings are part of the dataset cache key.
- **Featurization** (`soap.py`): computes SOAP (Smooth Overlap of Atomic Positions) descriptors from `Atoms` objects using `dscribe`.
- **Classical dimensionality reduction** (`pca.py`, `umap.py`, `utils.py` (z-score `fit_standardization`/`apply_standardization`)): thin, fit/transform-style wrapper classes around scikit-learn's `PCA` and `umap-learn`'s `UMAP`, both validating `n_components` and raising if used before fitting. `UMAP.__init__` also takes optional `n_neighbors`/`min_dist`/`metric`/`random_state`, each `None` by default -- left unset, that hyperparameter is whatever `umap-learn` itself defaults to (rather than this wrapper re-picking its own defaults), and only the ones actually given get forwarded to the underlying `SklearnUMAP`.
- **`analysis/`**: see `src/dim_red/analysis/CLAUDE.md`.
- **`generate.py`**: an alternative to `fetch.py` for building a structure database — generates synthetic, symmetry-valid structures from scratch with `pyxtal` (`GenerationConfig`/`generate_structures`) instead of querying Materials Project, returning the same `List[Atoms]` shape (`info["material_id"]`/`info["spacegroup"]`, plus `info["family"]`) so it's a drop-in alternative downstream. Configurable per-space-group or per-family (with uniform/random splitting across a family's space groups) structure counts, and how many chemical species per structure (which elements doesn't matter — sampled from a placeholder pool). Logs a warning for any space group whose Wyckoff multiplicities couldn't accommodate the requested structures. Not a hard dim_red dependency — requires `pip install pyxtal`. See `examples/pyxtal_structure_generation.ipynb` for a guided walkthrough, and `pipeline/dataset_cache.py`'s `RunConfig.data_source == "pyxtal"` for its pipeline integration: `RunConfig.fetch`/`RunConfig.pyxtal` are symmetric, data-source-specific config blocks (`pipeline/config.py`'s `FetchConfig`/`PyxtalConfig`), exactly one of which must be set matching `data_source` (YAML: `fetch:`/`pyxtal:` top-level blocks — `crystal_systems`/`limit_per_system`/`api_key` now live under `fetch:`, not a flat top level).
- **`supcon/`**: see `src/dim_red/supcon/CLAUDE.md`.
- **FullStack** (`model_kind: supcon` / `supcon_mace`, the only way to train them): one `family` stack (label = crystal system) plus up to 7 independent per-system experts (label = spacegroup), all the same `SingleStack` (`supcon/stack.py`: encoder + projection, then classifier + viz heads on the frozen encoder), each with its own pyxtal dataset, split, standardization and seed. Lives in `pipeline/full_stack.py` (train/predict/apply), `full_stack_config.py` (strict YAML schema: `family`, `experts.defaults` + per-expert overrides), `run_layout.py` (jax-free run reader), `featurize.py` (SOAP `mu2`/MACE features of new structures). `RunConfig`/`run_single` are cgcnn-only. Commands, layout and quirks: `docs/fullstack.md`, `src/dim_red/pipeline/CLAUDE.md`.
- **Traps**: GPU-trained stacks need `device="cpu"` on CPU-only machines (`FullStack.predict` defaults to it); `*_family_supcon` history keys also appear in experts (they contrast spacegroups); readers must ignore `.<x>.tmp` dirs (interrupted atomic writes); the strict YAML parser rejects old configs and `tests/test_example_configs.py` loads every shipped config; `data.soap.element_agnostic: true` (`mu2`) is required for `supcon`; old (pre-FullStack) run directories are not readable.
- **`cgcnn/`**: see `src/dim_red/cgcnn/CLAUDE.md`.
- **`mace/`**: see `src/dim_red/mace/CLAUDE.md`. A frozen, pretrained equivariant encoder (external `mace_jax` package, optional) whose embeddings feed `model_kind: supcon_mace` — the SupCon recipe on MACE embeddings, reusing all of `supcon/`.

**Optimizer**: always `optax.adam(learning_rate)` (VeLO was removed; a saved `train.optimizer` key is ignored). Family and experts share one implementation (`SingleStack`); the remaining refactor list is in `REFACTOR_TODO.md`.

**Early stopping** is implemented identically (duplicated code, same field names, same semantics) in the training loops (`supcon.training.training_first_phase`, `cgcnn.training.train_cgcnn`, plus the supcon phase-2 head loops in `supcon.tail_training`), via four `TrainConfig` fields: `early_stopping` (bool, default `False`), `early_stopping_patience`, `early_stopping_min_delta`, `early_stopping_restore_best`. It always monitors `val_loss` (the full weighted objective each history dict already always has) — not configurable to a different metric in this first pass. Mechanism: after each epoch, if `val_loss < best_val_loss - min_delta` the counter resets (and, if `restore_best_weights`, that epoch's `params` are snapshotted by reference — cheap, since `optax.apply_updates` returns a fresh pytree each step rather than mutating in place); otherwise the counter increments, and once it reaches `patience` the epoch loop `break`s. `model.params` is set to the snapshotted best params at the end when `restore_best_weights` is True (regardless of whether the loop broke early or ran to `epochs`), otherwise to the last epoch's. Returned `history` dicts are simply shorter than `config.epochs` when stopped early, so any per-epoch loop must use `len(history[...])` (`_save_loss_history` already does). `pipeline.config.EarlyStoppingConfig` (YAML: `train.early_stopping: {enabled, patience, min_delta, restore_best_weights}`) is the config-layer source; for cgcnn `run_single` copies it into `cgcnn.training.TrainConfig`, for FullStack `full_stack_config._train_config` copies it into the three `TrainConfig`s of each stack's `StackConfig` (`body_train`, `classifier_train`, `viz_train`). Default `enabled: false`. Caveat for `dimred-compare`: its "final metric" plots/CSVs read `loss_history[metric][-1]` (the last *logged* epoch) unchanged -- with `restore_best_weights=True` that can be a worse value than what the actually-restored `model.params` achieved a few epochs earlier, since the CSV still records every epoch including the non-improving ones that triggered the stop.

`dim_red/__init__.py` lazily imports `soap`, `fetch`, `analysis`, `supcon`, and `cgcnn` via module-level `__getattr__` (PEP 562) so that importing the base package doesn't require optional heavy dependencies (dscribe, mp_api, jax, flax, etc.) unless those submodules are actually used. `supcon/__init__.py` and `cgcnn/__init__.py` do the same lazy pattern internally for their own symbols. When adding new public symbols to any of these packages, follow this lazy-import pattern rather than importing eagerly at module top.
